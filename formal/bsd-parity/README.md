# BSD: a verified arithmetic improvement and a stricter specification

17 October 2026. Follow-on work on the BSD example published with Chris
Forrester's Ramtastic materials. This package is an independent contribution;
it does not imply Chris's review or endorsement.

**Result:** the four displayed points generate exactly the even-parity
subgroup of the reductions at 5, 13, and 19. Its size is **2,800**, inside a
product of **5,600** points. This is proved using Mathlib's actual elliptic-curve
point groups, including the discrete logs, generator orders, and exhaustive
coverage of each finite curve. It gives an exact structural explanation for
the factor of two observed in the published illustration.

A second component repairs the shape of the refined coefficient statement:
the arithmetic quantities are fixed before asserting equality, the regulator
is the Gram determinant, and change of basis carries the required square
factor. **Neither component proves BSD or determines the actual analytic rank.**

## The concrete curve and result

The generalized Weierstrass coefficients are `[1,-1,0,-79,289]`:

\[
E:\quad y^2+xy=x^3-x^2-79x+289.
\]

The four points, in the order used throughout the code, are
\(P_1=(6,-1),P_2=(4,3),P_3=(5,-2),P_4=(7,3)\).

| Prime | Group order | Cyclic generator | Logs of P1, P2, P3, P4 |
|---|---:|---|---|
| 5 | 10 | (1,0) | 9, 5, 8, 7 |
| 13 | 20 | (0,4) | 6, 8, 17, 10 |
| 19 | 28 | (0,2) | 9, 21, 5, 25 |

Let \(H\) be the subgroup of \(E(\mathbb F_5)\times E(\mathbb F_{13})
\times E(\mathbb F_{19})\) generated by these four simultaneous point tuples.
For any integer representatives \(a,b,c\), the theorem says

\[
(aG_5,bG_{13},cG_{19})\in H\iff a+b+c\equiv0\pmod2.
\]

This is a statement about the subgroup generated by the **four named points**.
It does not, by itself, identify the reduction image of every point of E(Q),
prove the frame is saturated, or supply a rational-point reduction homomorphism.

The proof is constructive. Integer words in the four generators with
coefficients `(5,5,0,3)`, `(3,9,3,2)`, and `(5,0,0,5)` give log triples
`(1,0,1)`, `(0,1,1)`, and `(0,0,2)`, respectively, modulo `(10,20,28)`.
If a+b+c is even, put t=(c-a-b)/2 and combine those words with coefficients
a,b,t. Conversely every generator has even total parity. For each of the
10×20 first-coordinate pairs there are exactly 14 admissible last coordinates.

Central declarations:

- `curve_joined_image_iff_even`: the exact characterization in the curve groups.
- `curve_reduction_image_card`: the actual generated subgroup has 2,800 elements.
- `curve_reduction_image_half_product`: the product has twice that cardinality.

An additional, explicitly exploratory exact-arithmetic check considered adding
Q=(8,7). It does not enlarge this subgroup: its logs are `(4,4,22)` and direct
rational group arithmetic gives Q=-P1-P4. This check is in the Python output,
not claimed as an additional Lean theorem or a saturation certificate.

## Repairing the refined coefficient clause

`FixedInvariants r` stores one Gram matrix and fixed period, Sha cardinality,
Tamagawa product, and torsion cardinality. Its regulator is **defined** as
`gram.det`. `FixedCoefficientStatement d C` is

\[
C=\frac{\Omega\det(G)\,\#\Sha\,\prod_p c_p}{\#E(\mathbb Q)_{\rm tors}^2},
\]

with every quantity on the right already supplied by d. The names indicate the
intended interpretation; this data structure does not establish it. In
particular, supplying a natural number named `shaCard` does not prove Sha finite.
This is a specification component, not an implementation of those invariants.

The package proves that fixed data determine a unique coefficient; under the
explicit positive-input assumptions that coefficient is positive. It also gives
a concrete positive-input counterexample showing that positivity alone does
not satisfy the fixed statement. There is no existential period that can be
chosen after seeing C.

The matrix theorem establishes
\(\det(U^TGU)=\det(U)^2\det(G)\). Unimodular changes preserve the regulator;
a frame change with determinant k multiplies it by k². Identifying |k| with
the index of an actual Mordell-Weil subgroup is a further arithmetic obligation.
These determinant identities are standard mathematics, not a novelty claim.

There are **52 named theorem declarations**, including finite arithmetic
certificates and helper lemmas. This is not a count of 52 new BSD results.
The axiom audit permits only `propext`, `Classical.choice`, and `Quot.sound`;

This is a focused follow-on to the earlier Zoo audit, not a claim that all Zoo

## Reproduce

This standalone package was checked with **Lean 4.28.0** and Mathlib commit
`8f9d9cff6bd728b17a24e163c9402775d9e6a365`. The supplied manifest pins all
dependencies. From this directory, with Lean/Elan and Python 3 installed:

```sh
lake exe cache get
bash verify.sh
```

The first command downloads dependency build artifacts; it is optional if
dependencies are already available or will be built from source. `verify.sh`
checks exact arithmetic, builds the proof library, prints every named theorem's
axioms, and rejects unexpected axiom dependencies. Results go into
`verification/`.

`generate_finite_curve.py` regenerates the finite-curve certificate source.
Generation is not trusted: Lean checks every generated assertion. No downloaded
dependency code or compiled binary is redistributed in this archive.

The inspected Ramtastic snapshot uses Lean **4.30.0-rc1**. This package does not
import that project, patch its sources, or claim its full build passes. Porting
these results into that versioned project remains an integration task.
The local verification reused pinned dependency caches; a pre-existing deletion
of `batteries/docs/README.md` is recorded in `verification/provenance.json`.
No tracked dependency Lean source was changed.
